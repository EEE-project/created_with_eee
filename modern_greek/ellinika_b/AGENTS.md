## Architecture — mixed backend, and it now varies by chapter

**Ellinika Β's noun/verb/adjective drill machinery historically ran on the older, separate `modern-greek-eee` + `modern-greek-inflexion-eee` packages (GitHub), not `eee_project` (Codeberg).** Confirmed by reading `chapter_08_notebook.py` directly:

```python
# dependency header:
#     "modern-greek-eee @ git+https://github.com/EEE-project/modern-greek-eee.git",
#     "modern-greek-inflexion-eee @ git+https://github.com/EEE-project/modern-greek-inflexion-eee.git",

# gu comes from a plain module import, not an instantiated class:
from modern_greek_eee import greek_utils as gu
```

Compare to every other course in this repo (Kapodistrias, Zorba, Odyssey, Palaestra, B1 grouping), where `gu` is an **instance** built from `eee_project`:
```python
from eee_project import GreekUtils
gu = GreekUtils(mg, mo, pd, eee_module=eee)
```

**As of 2026-07-23, ALL 10 verified chapters (1-4, 6-9, 11, 12) used this pattern — the old `gu`-only free-function API no longer existed anywhere in this course, but a second `gu` (the old module import) still sat alongside `gu2` for vocab-table plumbing (`get_words`, `load_data`, `TENSE_LABELS`).**

**As of 2026-07-28, `gu`/`modern_greek_eee` is gone entirely from all 10 base chapters — `gu2` alone now drives vocab-table plumbing too.** This directly supersedes "What to keep, what to replace" below, which documented why `load_data` in particular was kept on `gu`. Re-checked rather than assumed: every real call site guards `gu(2).load_data(...)` with `if file_upload_X.value:` first, so the one genuine behavioral difference (`GreekUtils.load_data` returns `None` on no-upload where the old module returned a default `DataFrame`) is provably unreachable here — the fallback branch never executes at any of the 30 call sites (3 per chapter × 10). `get_words`'s only difference (drops blank-`Word` rows) is a strict improvement, not a regression. Also fixed a real latent bug found along the way: `gu2`'s constructor was missing the `pd_module` argument in all 10 chapters — silently broken (would `AttributeError` on `self._pd`) the moment anything routed through it needed `self._pd`, which nothing did until this migration. Verified via full test suite + live interactive sessions (dropdown rendering, table selection) on multiple chapters, not just "0 errors" — see [[project_ellinika_b_gu2_migration]] in Claude's memory for the fuller investigation if picking this back up.

**Every chapter's cell IDs are their own thing, unrelated to any other chapter's** — confirmed repeatedly across the whole rollout (e.g. `tZnO`/`CLip`/`YECM` each mean a *different* cell in every one of chapters 6/7/8/9/11/12) — never assume an ID's meaning carries across chapters, even ones migrated back to back; always re-read each cell's actual content before touching it. See "Converting a chapter's test forms" below for the full worked history if a *new* chapter is ever added to the course.

The **index/topbar infrastructure is unified** — Ellinika Β's own `chapter_NN_notebook.py` and course `notebook.py` both use the normal `eee_project` `ConfigStore`/`eee_topbar` for navigation, same as everywhere else. It's specifically the drill machinery (noun/verb/adjective testing) that varies by chapter. Don't assume either API applies without checking the specific chapter's actual imports first.

```python
tense_selector = mo.ui.dropdown(options=_tense_options, value=_default_key, label=t_ui("tense_label", _lang))
```

  1. ## Verifying chapter_NN_extracted_content.md against the textbook

`chapter_NN_extracted_content.md` is a NotebookLM extraction — treat it as a draft, not ground truth. NotebookLM has bled content from adjacent chapters and invented ungrounded examples in this repo before (Chapter 1: 8 nouns + 3 verbs from Chapter 2 in the TEST WORDS section, an elision example that doesn't appear anywhere in Chapter 1, a Nom/Acc/Voc table that didn't match any grammar box in the chapter; Chapter 2: 7 of 26 vocabulary words and ~9 "room vocabulary" TEST WORDS that don't appear anywhere in the chapter, `nouns.tsv`'s first 8 entries were literally Chapter 1's grammar-paradigm words). The bleed goes in both directions — don't assume only "the current chapter minus one" is at risk. Before trusting an extraction, cross-check it page-by-page against `/home/sadov/work/greek/books/Ellininka/Ελληνικά Β - Επίπεδο Β1 - 2013.pdf`.

**Page numbering**: the PDF's internal page index is +1 off the printed page number in each page's own footer (PDF-internal N = printed page N-1). When a user cites "page N" for this book, don't assume which numbering they mean — check a page's own printed footer against what you'd expect.

**Transcribe verbatim, box by box — never merge, template, or genericize.** Each `Πώς το λένε;` / `Για δες` box is a separate, self-contained unit in the book; keep it that way in the extraction, one subsection per source page, phrases in the book's own order. Demonstrated failure modes:
- Merging near-duplicate phrases from different boxes into one invented composite row (e.g. collapsing "Παρακαλώ." / "Λέγετε;" / "Εμπρός;" / "Ορίστε;" — four separate greetings from three different boxes — into a single "/"-joined row).
- "Completing" a box's own phrasing with words the book didn't use (e.g. the book's own box says "Μπορώ να μιλήσω με την κυρία...;" — don't add "/τον κύριο" yourself just because it reads naturally).
- **Missing an entire second box on the same page.** A grammar page can carry more than one `Για δες` box side by side (e.g. Chapter 2 p. 28-29 has a definite/indefinite/no-article comparison table on p. 28 *and* p. 29 has its own separate definite-article box plus a much longer no-article list — it's easy to fully transcribe the first box, treat the page as done, and never notice the second one sitting right next to it). Scan the *whole* page image for every boxed unit before writing the section, not just the first one you recognize.
- **Flattening a paired weak/strong pronoun table into a generic summary.** The book prints personal-pronoun grammar (accusative in Ch. 1 p. 21, genitive in Ch. 2 p. 33) as **two parallel tables** — a weak-form table and a strong-form table — whose example sentences are literal continuations of each other, row by row (the strong-form sentence repeats the weak-form sentence and adds a contrastive tag or clarifying parenthetical). Collapsing this into one "Person | Weak | Strong" table plus a separate flat bullet list of examples loses the actual pairing relationship and is *not* what's on the page — reproduce it as the book's own two tables, "—" for any row the book itself leaves blank. This exact mistake happened independently in both Chapter 1 and Chapter 2 before being caught — treat any pronoun-paradigm box as a likely candidate for this, not just these two chapters.
- **Flattening a "Λέξεις, λέξεις" vocabulary box into a generic `Word | English | Russian | Type` table.** This box is not always a plain word list — the book routinely **bolds only part of an entry** to highlight the specific collocation being taught (e.g. p. 86: κρασί **χύμα** — "wine sold loose/on tap", not just "wine"; **παραγγέλνω** → παραγγελία, showing the verb→noun derivation with an arrow), and mixes in **multi-word phrases and idioms** that have no single-word form at all (δικής μας παραγωγής "of our own production"; μαθαίνω κάτι απ' έξω "to learn by heart"; φαγητό της ώρας "made-to-order food"; χάνω το χρώμα μου "to lose face"). Reducing every entry to a bare dictionary headword for a flat table drops the bold signal entirely and — worse — silently omits any entry that has no clean single-word form to put in the `Greek Word` column, since a table built by walking the *TSV candidates* rather than the *box itself* never has a row to put them in. Caught in chapter_06 (2026-07-23) — user spotted `κρασί χύμα`/`φαγητό της ώρας` missing from the `.md` entirely. **Fix: give each `Λέξεις, λέξεις` box its own per-page table** (same discipline as `Πώς το λένε;`/`Για δες` boxes), Greek column preserving the book's own bold inline (`κρασί **χύμα** (το)`), `Type` marking multi-word entries as `phrase`/`expression`/`idiom` (never `noun`/`verb`/`adjective` — those are reserved for genuinely single-word, TSV-drillable entries). Keep a separate "recurring vocabulary" table below the per-page ones for words that matter across the chapter but aren't from an explicit box — don't merge the two categories back together. Before adding any *new* single word surfaced this way to `nouns.tsv`/`verbs.tsv`/`adjectives.tsv`, confirm the backend actually has a paradigm for it (`gu2._paradigm(word, pos)` should return a non-empty dict) — chapter_06's own `μαγειρευτός` (from `μαγειρευτό φαγητό`) looked like a plausible standalone adjective but returned `{}`, i.e. not in the lexicon at all; it only exists in the `.md` as part of the phrase, not as a TSV row.

- **Assigning an unlabeled adjacent box to the wrong neighbor.** Not every box on a page carries its own icon+header — the book sometimes prints a second, visually plain panel right next to a labeled box, continuing that box's theme without repeating the label. Chapter_12 p. 191 has three panels at the bottom: a labeled green "Πώς το λένε;" box (4 lines), an unlabeled beige box of symptom/treatment collocations (βγάζω ακτινογραφία, έχω κάταγμα, ζαλίζομαι = νιώθω ζαλάδα, παίρνω παυσίπονα, βάζω πάγο), and a separate labeled "Λέξεις, λέξεις" notebook-icon box (6 bare headwords). The unlabeled middle panel is conversational-phrase content (verb collocations, "how you'd say it"), not vocabulary — it belongs with the green box, not the notebook-icon one. Caught 2026-07-23 when the user pointed at the beige box by name after the `.md` had folded it into the Vocabulary table instead: "'Πώς το λένε;' has more than 4 lines, look to this box." **Fix:** when a page has more than two boxes, don't default an unlabeled one to whichever named box is graphically closest or most similar in content-shape (word-list-shaped ≠ automatically "Λέξεις, λέξεις") — read the box's own *content register* (is it complete/near-complete utterances a speaker would say, or bare dictionary headwords?) and match it to the box it thematically continues. p. 187's "Πώς το λένε;" box on the same chapter, by contrast, really is just one labeled box with multiple internal sticky-note colors — not every multi-panel page has a hidden third box; check each one on its own terms.

Repetition across boxes (the same short phrase, e.g. "Εμπρός;", appearing in more than one box) is expected and correct — don't dedupe it away.

**Preserve bold-word highlighting in `Για δες` boxes**, and **check separately for color** — they are two different devices, not one. The book bolds the specific word (or case-ending, inside declension-table cells) that demonstrates the grammar point in each example sentence — real pedagogical signal, not typesetting decoration. Mark it with markdown `**bold**` when transcribing. Independently, the book also colors specific *letters* red inside some declension-table words, unrelated to the case-ending — confirmed on the word λέξη in **both** Chapter 1 (p. 17, Nom/Acc table) and Chapter 2 (p. 37, Genitive table): the letter **ξ** is red in every inflected form of λέξη, while the bold case-ending stays black. This looks like a spelling callout for that one letter (ξ = a single letter for /ks/, a common learner confusion with κσ) — not a grammar highlight, and not something to skip just because it isn't bold. Represent it in the `.md` file with inline HTML (`λ<span style="color:#c00">έξ</span>η`) — renders red on GitHub and in this repo's own notebooks, reads as plain text elsewhere — and carry the *same* real color into the notebook cell (see below), not just a text note. `Πώς το λένε;` phrase boxes are plain text with neither device — don't invent emphasis there.

**`Φωνή-γραφή` (pronunciation/spelling rules) is a real 4th segment type**, confirmed present in Chapter 1 (pp. 18, 20, 22 printed) and Chapter 2 (p. 38) but **not documented in `modern-greek-eee-skills`'s `ellinika-segments.md`**, which only covers the three standard segments (`Λέξεις, λέξεις` / `Πώς το λένε;` / `Για δες`). Check for it in every chapter and give it its own section in the extraction when present — it doesn't fit cleanly under GRAMMAR. Its rules are chapter-specific (Ch. 1: σ/ς+π/τ/κ nasal assimilation, τ'/μ'/σ' elision; Ch. 2: σ/ς voicing before voiced consonants, μου/σου/του elision) — don't assume one chapter's rules apply to another.

## Grammar/Pronunciation example sentences can be untranslated even when Phrases cells are fine — checked and fixed 2026-07-24

## marimo-pair note

Hit `StaleCellError` on a freshly-opened `code_mode` context while editing these notebooks (even on the first `edit_cell` call) — this is a general marimo-pair gotcha, not specific to this course. Fix and full explanation: `marimo-pair`'s own `reference/gotchas.md`.

**Establishing a session on a `--headless` marimo server with no browser available** (e.g. Chrome extension not connected): `execute-code.sh`/`code_mode` both need an *active session* (`GET /api/sessions` non-empty) — a bare running server process isn't enough, and `--headless` never auto-opens one. Open a real WebSocket connection to `ws://127.0.0.1:{port}/ws?session_id={any-uuid}&file={absolute-path-to-notebook}` (Python's `websockets` library; `session_id`/`file` are marimo's own query-param contract, see `marimo/_server/api/endpoints/ws/ws_connection_validator.py`) and keep it open in a background process — this alone registers a real session, which `execute-code.sh --session {same-uuid}` (or `--port`, auto-selecting the sole session) can then drive normally. A session opened this way has **never auto-run its cells** the way a real browser page-load would — the first `code_mode` operation on it will `NameError` on names a normal session would already have (e.g. a TSV-loader's `df_noun` not existing yet when a downstream table cell runs) even though `full_scan.py`-style "0 errors" checks looked clean beforehand (nothing had run yet to error). Fix: `for cid in list(ctx.cells.keys()): ctx.run_cell(cid)` once, in file/dict order, before doing anything else — marimo's reactive graph resolves correctly cascading top-to-bottom on a freshly-parsed notebook.

**A source edit to `eee_project` (or any editable-installed dependency) never reaches an already-running kernel** — every live session imported the package once at startup; Python's `sys.modules` cache means new methods/functions you add afterward are invisible even though the venv's editable install *does* point at your edited files (`pip show eee-project` confirms `Editable project location`). `importlib.reload()` alone isn't enough either: it re-executes the module and rebinds the module's own `GreekUtils` name to a new class object, but an *already-constructed* `gu2 = GreekUtils(...)` instance's `type(gu2)` still points at the pre-reload class — reload doesn't retroactively re-parent existing instances. Fix, in one `code_mode` call, per live session that needs the new code: delete every `eee_project`/`eee_project.*` key from `sys.modules`, `import eee_project.notebook_utils as new_nu`, then `type(ctx.globals["gu2"]).ui_label = new_nu.GreekUtils.ui_label` (patch the specific new attribute onto the *live* class object, not just re-import) — confirmed this makes the new method immediately callable on the existing `gu2` with no kernel restart. Matches this project's own "reload+patch, don't restart" convention.
